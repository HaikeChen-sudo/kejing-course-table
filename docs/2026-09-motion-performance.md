# 华理 0.1.38 动画与页面性能

## 改动

- 今日卡片不再逐帧改变字号、重排文本，也不再叠加三套高度动画。文字通过图层缩放与位移变化，卡片高度由一处插值控制。
- 主页面放在导航覆盖层下方。访问过的今日、周课表、备忘录保留布局；隐藏页不放置、不绘制、不接收触摸。详情和新增页面覆盖主页面，返回不重建周网格。代价是最多保留三个主页面的内存。
- 底栏与主页面保持同一布局，不在返回开始时突然改变页面高度。详情、新增页使用不透明滑入滑出，底部主页面切换不做全屏透明度混合。
- 过渡中重复打开或返回的按钮调用被生命周期检查拦住。
- 启动动画结束后准备周课表，周课表再预加载相邻各一周。课程斜纹裁剪在卡片内，避免越界覆盖整张网格。
- 节次滚轮只在范围或标签改变时更新数据，不在每次更新时反射修改文字颜色。修正选中项偶尔只显示裸数字的问题。

## 构建

新增 `performance` 构建：关闭调试，启用 R8 与资源优化，并打包依赖自带的 ART profile。沿用本机 debug 签名以兼容手机上已有安装；这不是应用商店正式发布签名。没有伪造应用专属 Baseline Profile，也没有对手机执行仅本机生效的强制全量预编译。

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:assemblePerformance :app:testDebugUnitTest
```

非调试包不能使用 `run-as` 读取私有数据。切换前已在 `/private/tmp/coursia-device-check/before-performance038.tar` 保存课表与设置备份。优化包可原位升级，不需要卸载。

依据：[Compose 官方性能说明](https://developer.android.com/develop/ui/compose/performance)。官方要求在优化的非调试构建上评估性能，建议减少重复组合、延后动画状态读取和使用预编译配置。

## 实机记录

设备 67556bd3，1280×2772。测量与录屏分开进行，不录屏采集 `dumpsys gfxinfo`；每组先清空统计。不是跨机型基准，也不能据此承诺每一帧都达到 120 Hz。

| 操作 | 0.1.37 debug P95 | 0.1.38 performance P95 |
|---|---:|---:|
| 今日第一张卡片展开收起 12 次 | 29–32 ms | 8 ms |
| 今日／本周连续切换 16 次 | 44–48 ms | 24 ms |
| 详情打开返回 6 轮 | 150 ms | 17 ms |
| 新增页面打开返回 6 轮 | 125 ms | 17 ms |
| 周课表左右滑动 4 轮 | 29 ms | 15 ms |

这张表比较用户原安装包与优化候选包，是代码调整和构建优化的合并效果。仅代码修改、仍为 debug 时，保留主页面后的详情 P95 为 42 ms，新增为 34 ms。早期存在人工操作干扰、切到桌面或零帧的轮次已排除。

优化候选包首次进入周课表加首次拖动的 P95 为 36 ms，P99 为 150 ms。随后补充了启动后准备周课表，最终首次操作结果需单独复测，不能套用上表热路径数据。

检查已采集统计：

```sh
bash scripts/check-frame-timing.sh /private/tmp/coursia-device-check/detail-performance038.txt
```

默认 P95 阈值 33 ms 仅用于发现严重长帧回归，不是“完全流畅”的标准。脚本对无样本返回 INVALID，对旧详情样本返回 FAIL，对新详情样本返回 PASS。

单次操作样本、重复测量、返回视觉验证与首次操作应分开；测试前确认应用在前台、屏幕亮起且对应页面确实有课程。不能把无效坐标点击或零帧统计当作性能改善。
